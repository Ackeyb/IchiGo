# IchiGo v5 変更仕様書

## 0. 文書の位置づけ

本書は、IchiGo v4 から v5 への変更仕様を定義する。

v5 は大規模なゲームルール追加ではなく、主に以下を目的とする微調整リリースである。

- 連続試合の途中結果導線を簡略化する
- 連続試合の最終試合で暫定情報を秘匿し、最終結果の公開タイミングを明確にする
- 完走指定における「target 未達による継続」と「Sudden Death」を概念上・実装上分離する
- Recovery schema を v5 の進行意味論に合わせて更新する

v4 の既存仕様・実装・テストを基礎とし、本書に明記されていない v4 の挙動は原則として維持する。

---

# 1. v5 の変更概要

## 1.1 連続試合

- 最終試合以外の試合終了時、従来の「結果を見る」→ Intermediate →「次の試合へ」という導線を使用しない
- Play 画面上の終了 Action を直接「次の試合へ」とする
- 「次の試合へ」を押すと Intermediate 画面を表示せず、次の試合へ移行する
- Intermediate 画面および関連コードは削除しない
- 将来オプション等で再利用できるよう残す
- 最終試合終了時のみ「結果を見る」を維持する
- 最終試合中は Play 画面下部の暫定順位と累計 Score を「ヒミツ」としてマスクする
- 累計 Remaining は表示する
- 最終試合中は暫定最下位 highlight を表示しない
- Final Ranking を開いた時点で初めて最終順位・累計 Score を公開する

## 1.2 完走指定

- target 未達で Game が終了した場合、それを Sudden Death と扱わない
- target 未達時は通常の次 Game として継続する
- Play 画面上の終了 Action は「次の試合へ」とする
- 結果画面を挟まず次 Game へ進む
- Score / Remaining / per-Game state は Game ごとに reset する
- `totalCompletionCount` のみ累積する
- target 達成済みで Normal の Sudden Death 条件が成立した場合のみ、本当の Sudden Death とする
- 本当の Sudden Death へ進む Action は「サドンデスへ」とする
- target 達成済みかつ Sudden Death 不要の場合は「結果を見る」とする

## 1.3 Recovery

- Game Recovery schema を 5 へ更新する
- schema 4 は unsupported とし、migration しない
- missing field や旧意味論を Normal / v5 state として推測補完しない
- Sound schema は引き続き 1 を維持する

# 3. 用語整理

## 3.1 Game

各プレイヤーが 1 Turn ずつ行う一単位。

v5 の完走指定では、target 未達時に次の Game へ進む。

## 3.2 Sudden Death

v5 では、完走指定において以下の場合だけを Sudden Death と呼ぶ。

- target 達成済みかつ全員 Complete
- target 達成済みかつ全員 non-complete で Score / Remaining が完全一致

target 未達による継続は Sudden Death ではない。

---

# 4. 連続試合 — 途中試合終了導線

## 4.1 現行 v4

v4 では最終試合以外の Series Game 終了後、

1. 「結果を見る」
2. Intermediate 画面
3. 「次の試合へ」
4. 次 Game

という導線を持つ。

## 4.2 v5

v5 では最終試合以外について、

1. 最後の player の Turn 終了
2. current Game contribution を authoritative cumulative へ commit
3. save attempt
4. 最後の ROLL presentation 完了
5. Play 画面上の Action を「次の試合へ」と表示
6. user が「次の試合へ」を押す
7. Intermediate 画面を表示せず次 Game 開始

とする。

---

# 5. 連続試合 — Intermediate 画面の扱い

## 5.1 削除しない

Intermediate 画面および関連コードは削除しない。

理由：

- 将来、途中結果表示を option 化する可能性がある
- 将来、表示 ON / OFF を選べる可能性がある
- v4 互換の表示構造を再利用できる余地を残す

## 5.2 v5 の標準 Flow

v5 の標準 Flow では Intermediate を bypass する。

Intermediate component / helper / domain support がコード上未使用に見える状態になっても、本仕様上は意図的に保持する。

不要コードとして勝手に削除しない。

## 5.3 option 自体は実装しない

v5 では `showIntermediateResults` 等の新設定は実装しない。

将来拡張可能性だけ残す。

最終試合終了後の Action：

# 7. 連続試合 — 最終試合の情報マスク

## 7.1 目的

最終試合中に最終順位や累計 Score が見え続けると、最終結果の公開前に結果がほぼ判明する。

v5 では最終試合中の Play 画面で、最終結果に直結する情報を意図的に秘匿する。

## 7.2 マスク対象

最終試合開始時から Final Ranking 公開まで、Play 画面下部の以下をマスクする。

- 暫定順位
- 累計 Score

表示文字列：

**「ヒミツ」**

## 7.3 表示を維持するもの

以下は表示する。

- player name
- 累計 Remaining
- current Game の通常 Play 情報
- 試合 current / total
- ROLL counter（finite の場合）

## 7.4 暫定最下位 highlight

最終試合中は暫定最下位 highlight を表示しない。

理由：

順位文字列を「ヒミツ」としても、最下位 highlight が残ると順位情報が漏れるため。

## 7.5 マスク開始タイミング

最終試合開始直後からマスクする。

## 7.6 マスク解除タイミング

最終 player の Turn が終了しても、Play 画面上ではマスクを維持する。

user が「結果を見る」を押し、Final Ranking 画面へ移行した時点で初めて公開する。

---

# 8. 連続試合 — マスク対象値の authority

最終試合中も内部では従来どおり、

- provisional cumulativeScore
- provisional cumulativeRemainingDice
- provisional rank
- provisional bottom rank

を正しく計算する。

マスクは presentation 上の処理とする。

authoritative / derived state の計算を停止しない。

Final Ranking は既存 Series Final Ranking の authority をそのまま使用する。

---

# 9. 連続試合 — 最終試合の暫定表示

最終試合では、各 player row の概念的表示を以下とする。

- 順位：ヒミツ
- Score：ヒミツ
- Remaining：8

既存 UI の label / table 構造に合わせて表現してよい。

`---`、`???`、空欄等へ変更しない。

---

# 10. 連続試合 — Stable Layout

最終試合マスクのために Play layout を変更しない。

禁止：

- 行削除
- column 削除
- element reorder
- Action Slot 移動
- reserved region 変更
- sticky / fixed / absolute hack
- overflow hidden
- touch target 縮小
- animation 短縮

数値の代わりに「ヒミツ」を表示するだけで、既存の領域を維持する。

---

# 11. 完走指定 — v5 の基本進行

完走指定では、target 達成まで複数 Game を行う。

各 Game：

- 全 player が 1 Turn ずつ
- completion event は `totalCompletionCount` へ加算
- target 未達でも全 player の Turn 終了まで継続
- Game 終了時に target を判定

---

# 12. 完走指定 — target 未達

Game 終了時：

`totalCompletionCount < targetCompletions`

なら、その Game では決着しない。

v5 ではこれを Sudden Death と呼ばない。

通常の次 Game へ進む。

---

# 13. 完走指定 — target 未達時の Action

target 未達 Game 終了後：

**「次の試合へ」**

を表示する。

従来の「結果を見る」は表示しない。

途中結果画面を挟まず、user が押すと次 Game を開始する。

---

# 14. 完走指定 — target 未達 Game の reset / carry

次 Game へ進む際に維持：

- participants
- player IDs
- original order
- Dice Mode
- Throw Style
- Game Mode
- targetCompletions
- RollLimit = null
- totalCompletionCount

reset：

- current Game score
- activeDice
- strandedDice
- removedDice
- completed state
- current player
- Turn progress
- ROLL number
- current Game result
- per-Game visible / presentation state

過去 Game の Score / Remaining は Ranking へ持ち越さない。

---

# 15. 完走指定 — completion count

`totalCompletionCount` は completion event の累積。

例：

target = 3

Game 1：
- A Complete
- total = 1

Game 2：
- A Complete
- total = 2

Game 3：
- B Complete
- C Complete
- total = 4

Game 3 終了時：

- target 達成済み
- count は 4 のまま
- 3 へ clamp しない

同じ player が複数 Game で Complete しても毎回加算する。

---

# 16. 完走指定 — target 達成後の決着判定

Game 終了時に target 達成済みなら、Normal の Sudden Death 条件を確認する。

## 16.1 全員 Complete

Sudden Death。

## 16.2 全員 non-complete かつ Score / Remaining 完全一致

Sudden Death。

## 16.3 上記以外

その Game を decisive Game とし、Ranking へ進む。

---

本当の Sudden Death 条件が成立した場合の Action：

**「サドンデスへ」**

とする。

「次の試合へ」とは表示しない。

# 18. 完走指定 — 決着 Action

target 達成済みで Sudden Death 不要の場合：

押すと Final Ranking / loser / Penalty へ進む既存契約を使用する。

# 20. 完走指定 — Sudden Death と通常 Game の区別

## 通常 Game 継続

理由：target 未達。

表示：**次の試合へ**

## Sudden Death

理由：target 達成済みだが Normal の完全同率条件が成立。

表示：**サドンデスへ**

---

# 21. 完走指定 — identity

target 未達による通常継続と Sudden Death を区別できる state / identity を持つこと。

既存 Normal 用 Sudden Death identity を target 未達継続へ流用しないことを推奨する。

ただし不要な duplicate authority は追加しない。

---

# 22. 完走指定 — UI 上の progress

新たな「試合 x / y」のような total game count 表示は追加しない。

完走指定は必要 Game 数が事前に確定しないため。

既存の：

**完走 current / target**

を維持する。

---

# 23. 完走指定 — 中間結果画面

target 未達時は途中結果画面を表示しない。

Play 画面から「次の試合へ」で直接次 Game へ進む。

将来再利用可能な既存 component を、未使用であることを理由に削除しない。

---

# 24. 完走指定 — Sudden Death 表示

Sudden Death へ進む場合も、途中 Ranking を表示してから進む必要はない。

Play 画面上の Action：

**「サドンデスへ」**

から直接次 Sudden Death Game へ進む。

既存 staged presentation は維持する。

---

# 25. 完走指定 — decisive Game

target 達成済みで Sudden Death 不要の場合、その current Game が decisive Game。

Ranking には current Game のみ使用する。

過去 Game の Score / Remaining / complete flag / Ranking は加算しない。

`totalCompletionCount` のみ累積値として Penalty multiplier に使用する。

---

# 26. 完走指定 — Penalty

Penalty は v4 と同じ。

- decisive Game の loser
- decisive Game の remainingDice
- single-roll Penalty
- OUT supported
- multiplier = totalCompletionCount + 1

Series Penalty chunk logic は適用しない。

Normal の「結果を見る」、Final Ranking、Sudden Death、Penalty、provisional Ranking、Complete 優先、ROLL limit 等は現行 v4 を維持する。

# 30. Recovery — 推測補完禁止

禁止：

- schema 4 state を schema 5 として読み替える

- missing mode を Normal と推測
- Sudden Death state を target 未達 Game と推測
- target 未達 state を Sudden Death と推測
- corrupt data の repair

invalid / unsupported は既存 discard path を使用する。

# 31. Recovery — 連続試合

## 非最終試合

Game 終了 Action 待ちで Recovery された場合：

- Intermediate を自動表示しない
- 「次の試合へ」待ちを復元する
- cumulative state を再加算しない

## 最終試合

最終試合 Play 中に Recovery した場合：

- 暫定順位 = ヒミツ
- cumulative Score = ヒミツ
- cumulative Remaining = 表示
- bottom highlight = 非表示

Final Ranking phase なら通常どおり公開する。

---

# 32. Recovery — 完走指定

## target 未達

- 「次の試合へ」待ちを復元
- Sudden Death として復元しない
- `totalCompletionCount` を保持

## target 達成 + Sudden Death

- 「サドンデスへ」待ちを復元
- Sudden Death identity / phase を保持

## target 達成 + decisive

- 「結果を見る」待ち / Result phase を復元

# 41. Series cumulative commit

v5 の UI bypass によって、Series の atomic cumulative commit を変更しない。

最後の terminal ROLL で current Game contribution は一度だけ authoritative cumulative へ commit される。

「次の試合へ」押下時に再加算しない。

# 42. Series provisional ranking

2. provisional cumulativeRemainingDice ASC
3. exact tie

ただし最終試合では UI 上 rank / Score を「ヒミツ」として表示する。
