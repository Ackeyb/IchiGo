# IchiGo v4 変更仕様書

## 1. 目的

v4では、既存のゲーム進行を維持する「ノーマル」に加え、「完走指定」「連続試合」の2つのゲームモードを追加する。

また、ゲームルールをまとめて確認できる「ルール説明」ページを追加する。

v4では既存v3のゲームルールを可能な限り再利用し、**ノーマルモードの挙動を変更しないこと**を重要な互換条件とする。

---

## 2. v3から変更しない基本仕様

以下は、特記がない限りv3の現行仕様を維持する。

- プレイヤー数：2～10
- Dice Mode：5 / 7 / 10 / 14
- デフォルトDice Mode：7
- Throw Style：rough / normal / careful
- OUT率：rough 3% / normal 1% / careful 0%
- OUT判定は各die独立
- 各dieはOUT判定を先に行い、SAFEの場合のみD6 faceを生成する
- OUTのauthoritative表現は `{ status: "out", value: null }`
- 通常Playの1 / 5 scoring
- scoring die removal
- stranded OUT
- Complete判定
- No Score判定
- ROLL上限
- Penalty OUT
- Sound
- Three.js / 2D fallback
- Session Recoveryの基本思想
- Rendererはauthoritative game logicを持たない
- committed result → save attempt → presentation の順序
- staged presentation
- Mobile Stable Layout

v4追加機能のために必要な場合を除き、これらの既存仕様を変更しない。

---

## 3. 用語

### 3.1 Turn

1プレイヤーが行う一連のPlay。既存v3と同じゲームルールに従い、terminal stateへ到達するまで継続する。

終了判定優先順位も既存仕様を維持する。

```text
COMPLETE
> no-score
> ROLL limit
> no-active-dice
> continue
```

### 3.2 Round

全参加プレイヤーが1Turnずつ終了するまでを1 Roundとする。Sudden Deathが発生した場合、新しいRoundを開始する。

### 3.3 Series Game

連続試合モードにおける1試合。全参加プレイヤーが1Turnずつ終了した時点で1 Series Game終了とする。Series Game内部ではSudden Deathを行わない。

### 3.4 Series

連続試合モードで指定された2～5回のSeries Game全体を指す。

## 4. Game Mode

SetupへGame Modeを追加する。

表示名：

```text
ノーマル
完走指定
連続試合
```

デフォルトは「ノーマル」。

3モードは相互排他的とし、同時に複数モードを有効にできない。内部stateでもこの排他性を保証する。

推奨モデル：

```ts
type GameMode =
  | { type: "normal" }
  | {
      type: "completionTarget";
      targetCompletions: 1 | 2 | 3 | 4 | 5;
    }
  | {
      type: "series";
      gameCount: 2 | 3 | 4 | 5;
    };
```

具体的な型名は既存code styleに合わせてよい。

重要なのは、**選択されていないモードの設定値をauthoritative configurationとして同時保持しないこと**である。

---

## 5. Setup UI

Game Mode選択はプレイヤー設定の下に配置する。

```text
プレイヤー設定
↓
Game Mode
↓
選択モードに対応する設定
```

Game Modeを先に選択し、選択されたモードで使用する設定だけを展開する。

共通設定はDice ModeとThrow Style。モード固有設定は後述する。

Setup追加を理由に既存Mobile Stable Layoutへ不要な構造変更を行わない。

---

## 6. ノーマル

表示名は「ノーマル」。

現行v3のゲーム進行そのものとする。以下を含む既存仕様を変更しない。

- Ranking
- Complete優先
- Sudden Death
- exact tie
- loser detection
- Penalty
- ROLL上限
- totalCompletionCount
- Penalty multiplier

Game Mode abstraction追加を理由に、ノーマルのゲームルールを再実装・再解釈しない。

---

## 7. 完走指定

表示名は「完走指定」。

### 7.1 設定

設定項目は「最低完走者数」。

設定可能値：1 / 2 / 3 / 4 / 5

初期値：1

ここでいう完走者数はunique player数ではなく、**completion eventの累積回数**を意味する。同一プレイヤーが複数Roundで完走した場合、その都度+1する。既存の`totalCompletionCount`と同じ意味で扱う。

---

## 8. 完走指定とROLL上限

完走指定では`ROLL上限 = ∞`を強制し、有限ROLL limitは禁止する。

完走指定を選択した時点でauthoritative RollLimitをunlimitedへ変更する。以前選択されていた有限値は保持・復元しない。

ノーマルまたは連続試合へ戻った場合もROLL ∞から開始し、必要であればユーザーが再設定する。

Setupでは、完走指定を選択中は**ROLL上限UI自体を非表示**とする。

概念的な表示：

```text
Dice Mode
Throw Style
最低完走者数
```

---

## 9. 完走指定のRound進行

各Roundでは、全参加プレイヤーが通常どおり1Turn行う。

途中で累積完走数が指定数へ到達しても、その場でRoundを終了しない。必ず残りのプレイヤーもTurnを行う。

Round終了後に初めて決着条件を評価する。

---

## 10. 完走指定の未達時

Round終了時点で`totalCompletionCount < targetCompletions`の場合、そのRoundでは決着しない。

既存Sudden Deathと同様に、全参加プレイヤーで次Roundへ進む。

維持するもの：

- original players
- original order
- Dice Mode
- Throw Style
- Game Mode
- completion target
- totalCompletionCount

resetするもの：

- score
- activeDice
- strandedDice
- removedDice
- Turn progress
- ROLL number
- Round内result

Roundごとのscoreおよびremaining diceは次Roundへ持ち越さない。

---

## 11. 完走指定の決着

Round終了時に`totalCompletionCount >= targetCompletions`であり、かつloserが存在する場合、そのRoundでゲームを終了する。

ゲーム全体の敗者はtarget到達Roundの最終敗者とする。

過去Roundのscore・remaining diceは最終Rankingに使用しない。

Rankingにはtarget到達Roundのcompletion state / score / remaining diceのみを使用し、既存ノーマルのRanking規則を適用する。

---

## 12. 完走指定でSudden Deathを続行する条件

targetへ到達したRoundであっても、既存Normalルール上Sudden Deathとなる完全同率状態では決着しない。

対象：

- 全プレイヤーがComplete
- 全プレイヤーがnon-completeで、scoreおよびremaining diceが完全一致

この場合は全参加プレイヤーでSudden Deathを続行する。

`totalCompletionCount`はresetしない。

一度targetを超えた後はtarget条件は既に成立済みとして扱う。

Completion TargetはSudden Deathの同率判定そのものを変更しない。

その後最初に、

```text
Round終了
かつ
target条件成立
かつ
既存Normalルール上Sudden Death不要
かつ
loserが存在する
```

状態となったRoundで決着する。

---

## 13. 完走指定の進捗表示

Play中に`完走 current / target`相当の情報を確認できるようにする。

例：

```text
完走 2 / 3
```

targetへ到達しているがRound終了待ちの場合も、条件達成が視認できるようにする。

ただし既存Play画面のStable Layoutを崩してはならない。

新しい表示のために以下を行わない。

- Actionを移動する
- presentation regionを縮める
- reserved regionを削る
- sticky / fixed UIを追加する
- overflowで隠す
- animationを短縮する

可能な限り既存の予約済み情報領域内で表示する。

## 14. 連続試合

表示名は「連続試合」。

---

## 15. 連続試合の設定

設定項目は「試合数」。

設定可能値：2 / 3 / 4 / 5

初期値：2

1試合は設定不可。

ROLL上限は使用可能。

---

## 16. Series Game進行

各Series Gameでは、全プレイヤーが通常Playと同じTurnを1回行う。

Turnは既存ルールどおり終了する。ROLL limitが有限の場合、その設定も通常どおり適用する。

全プレイヤーのTurn終了後、そのSeries Gameを終了する。

Series Game単位では以下を行わない。

- winner確定
- loser確定
- Penalty
- Sudden Death

---

## 17. Series Game終了時の累積

各Series Game終了時、プレイヤーごとに以下を累積する。

- cumulativeScore
- cumulativeRemainingDice

`cumulativeScore`には今回Gameのscoreを加算する。

`cumulativeRemainingDice`には`activeDice + strandedDice`を加算する。

CompleteしたGameではremaining = 0として加算する。

各Gameの個別score・dice stateは次Gameへ直接持ち越さない。次Game開始時には通常のinitial player stateへresetする。

---

## 18. 連続試合の完走回数

各Series Gameで発生したCompleteは、シリーズ全体の`totalCompletionCount`へ累積する。

同じプレイヤーが複数GameでCompleteした場合も、そのたびに+1する。

この値は最終Penalty multiplierへ使用する。

---

## 19. Series Game間で維持するもの

維持：

- original players
- player order
- Dice Mode
- Throw Style
- ROLL limit
- Series game count
- current game number
- cumulativeScore
- cumulativeRemainingDice
- totalCompletionCount

reset：

- current game score
- activeDice
- strandedDice
- removedDice
- current Turn progress
- ROLL number
- per-game result

---

## 20. Series Game間画面

Series Game終了後、最終Gameでない場合は専用の中間画面を表示する。

表示内容：

- 現在終了した試合番号
- 全試合数
- 各プレイヤーの累積Score
- 各プレイヤーの累積残ダイス数
- 次の試合へ進む操作

例：

```text
試合 2 / 5 終了
```

この画面ではその時点の累積状況を表示してよいが、敗者確定・Penalty・最終勝敗確定は行わない。

---

## 21. 連続試合の進捗表示

Play中にも`試合 current / total`相当の情報を表示する。

例：

```text
試合 2 / 5
```

既存Play画面のStable Layoutを維持する。

---

## 22. 連続試合の最終Ranking

指定された全Series Game終了後、累積値のみでRankingする。

第1比較：

```text
cumulativeScore DESC
```

累積Scoreが高いほど上位。

完走者を無条件で上位にするノーマルRankingルールは使用しない。

第2比較：

```text
cumulativeRemainingDice ASC
```

累積残ダイス数が少ないほど上位。

それでも完全一致する場合は同順位とする。

既存と同じcompetition rankingを使用する。

例：

```text
1
2
2
4
```

---

## 23. 連続試合の敗者

最終Rankingで最下位rankとなったプレイヤー全員を敗者とする。

人数制限なし。

- 最下位1人 → 1人Penalty
- 最下位3人 → 3人全員Penalty
- 全員同順位 → 全員Penalty

連続試合では、最終Rankingが全員同順位でもSudden Deathを行わない。

---

## 24. 累積remainingが0の敗者

敗者の`cumulativeRemainingDice = 0`の場合、Penalty用diceは0個となる。

この場合はROLLしない。

```text
BASE = 0
FINAL = 0 × multiplier = 0
```

最低1dieを強制するルールは追加しない。

---

## 25. 連続試合Penalty multiplier

シリーズ中の全Complete回数を累積した`totalCompletionCount`を使用する。

既存仕様と同じ、

```text
multiplier = totalCompletionCount + 1
```

とする。

各Series Gameごとにはresetしない。

---

## 26. 連続試合Penalty dice count

Penaltyでは敗者の`cumulativeRemainingDice`を使用する。

Dice Modeの現在値ではなく、シリーズ全体で累積した残ダイス数がPenalty dice countとなる。

最大例：

```text
14 DICE × 5 Games = 70 dice
```

---

## 27. Penalty chunk

累積Penalty diceが10を超える場合、1回のRenderer presentationへ全diceを渡さない。

最大10 dice単位のchunkへ分割する。

```text
15 → 10 + 5
24 → 10 + 10 + 4
30 → 10 + 10 + 10
70 → 10 + 10 + 10 + 10 + 10 + 10 + 10
```

chunk順は先頭から順に処理する。

### 27.1 Series Penalty chunkの2D配置

Series Penalty chunkは元のDice Modeとは独立したpresentation unitとして扱う。

2D result layout：

```text
10 → 5 + 5
9  → 5 + 4
8  → 5 + 3
7  → 5 + 2
6  → 5 + 1
≤5 → 1 row
```

元のDice Modeが5または7であっても、10 dice chunkを拒否しない。

この規則はSeries Penalty chunkの2D result presentation専用であり、通常Playのresult layoutやThree.js staging layoutへ適用しない。

元のゲームDice Mode自体を変更してはならない。

---

## 28. Penalty chunkのユーザー操作

敗者1人につき、Penalty開始時にユーザーが1回だけROLL操作を行う。

その1操作でその敗者のPenalty sequenceを開始する。

2つ目以降のchunkはユーザーの追加操作なしで自動ROLLする。

複数敗者がいる場合は、既存仕様どおりoriginal player orderで個別処理する。

次の敗者は、前の敗者のPenalty完了後に処理する。

---

## 29. Penalty chunk間のWait

各chunkのpresentationが完了したあと、次chunkを自動ROLLするまで1500ms待機する。

Waitの目的は、直前chunkの結果をプレイヤーが視認できる時間を確保することである。

Waitをanimation途中から計測しない。

ここでいうpresentation completeは、Rendererのanimation停止だけではなく、当該chunkについて必要なrevealとpaint acknowledgmentまで完了し、次のActionを進めても表示が追いついている状態を指す。

```text
chunk authoritative result commit
↓
save attempt
↓
presentation
↓
reveal / paint acknowledgment complete
↓
1500ms wait
↓
next chunk
```

### 29.1 Auto chunk wait中のblocking confirmation

Series Penaltyの1500ms auto-wait中に、ゲーム終了等のblocking confirmation dialogを開いた場合、pending auto-next timerをcancelする。

dialog表示中は以下を行わない。

- next chunkを生成しない
- RandomSourceを消費しない
- authoritative Penalty progressを進めない

確認をcancelしてPenaltyへ戻った場合は、残りwait時間を復元せずfresh 1500ms waitを開始する。

確認を確定した場合は、現行の終了処理へ進む。

cancel済みの古いtimer callbackは、revision / penalty identity / chunk progress guardによってauthoritative stateへ作用できないものとする。

---

## 30. Penalty chunkとOUT

各chunkは既存Penaltyと同じ生成ルールを使用する。

```text
OUT check
↓
SAFE only face generation
```

OUT probabilityは現在のThrow Styleを使用する。

OUT authoritative state：

```ts
{
  status: "out",
  value: null
}
```

OUTはBASE計算時のみ6として扱う。

保存時やRenderer入力時にSAFE 6へ変換しない。

---

## 31. Penalty chunkとROLL limit

通常PlayのROLL limitはPenalty chunkには適用しない。

Penalty chunk countが増えても、通常PlayのROLL limitを消費しない。

---

## 32. Penalty BASE

各chunkの結果を合計し、最終的なPenalty BASEを計算する。

例：

```text
24 accumulated dice
↓
10 dice BASE = 31
10 dice BASE = 28
4 dice BASE = 15
↓
TOTAL BASE = 74
```

その後、

```text
TOTAL BASE × multiplier = FINAL
```

とする。

multiplierをchunkごとに適用しない。

---

## 33. Penalty表示

Penalty chunk中は、現在のchunk・処理済み結果・必要なprogressをユーザーが理解できるようにする。

例：

```text
1 / 3
2 / 3
3 / 3
```

具体的な文言はUI設計時に既存styleへ合わせる。

ただし、Action Slot・Penalty reserved region・scroll位置・mobile stabilityを崩してはならない。

70 diceを一度に表示する必要はない。現在処理している最大10 diceのchunkを既存Rendererへ渡す。

---

## 34. 連続試合Penaltyの最終表示

全chunk終了後、

```text
全chunk BASE合計
MULTIPLIER
FINAL
```

を表示する。

複数chunkのdiceを一つの巨大なresult gridとして再表示する必要はない。

Recovery可能なauthoritative情報は保持する。

---

## 35. Game Recovery schema

v4ではGame Recovery schemaを4へ更新する。

既存v3 Game Recovery schemaからのmigrationは行わない。

schema 3の保存gameはunsupportedとして扱い、推測補完しない。

Sound persistenceはGame schemaとは独立して扱い、既存Sound schemaを変更しない。

---

## 36. Recovery — Game Mode

Recoveryには最低限Game Modeとmode-specific configurationを保存する。

mode-specific settingが選択モードと矛盾する保存stateはrejectする。

例：

```text
completionTarget + finite RollLimit
```

はinvalid。

選択されていないモード用の設定を推測して補完しない。

---

## 37. Recovery — 完走指定

保存対象：

- targetCompletions
- totalCompletionCount
- current Round state
- current player
- committed roll
- 既存Recoveryに必要なstate

Recovery後も`totalCompletionCount`を維持する。

既にtargetへ到達済みでもRound途中なら残りプレイヤーを続行する。

target到達だけを理由にRecovery直後にゲーム終了させない。

---

## 38. Recovery — 連続試合

保存対象：

- configured game count
- current game number
- cumulativeScore
- cumulativeRemainingDice
- totalCompletionCount
- current Series Game state
- current Turn state
- committed result
- Penalty progress
- Penalty chunk progress

等、途中resumeに必要なauthoritative state。

Recoveryで累積値を過去Gameから再推測しない。

保存されたauthoritative cumulative valuesをvalidatorで検証する。

---

## 39. Recovery — Penalty chunk

確定済みchunkをRecovery時に再抽選しない。

既にcommitされたchunkは同じ`DieResult[]`を復元する。

未実行chunkのみ新しいrandom generation対象となる。

同一chunkをRecoveryによって二重加算してはならない。

### 39.1 Auto sequence途中のreload

Penalty chunkの自動sequence開始後にreloadされた場合は、「敗者1人につき最初の1タップだけ」という操作契約を維持する。

Recovery後：

1. committed済みchunkを復元する
2. committed済みchunkをrerollしない
3. auto-sequence開始済み状態を復元する
4. 画面へ現在状態を復元する
5. 未実行chunkが残っている場合、復元後1500ms待機する
6. 次chunkを自動生成する

Recovery後に追加のROLLタップを要求しない。

WaitはRecovery後に新しく1500ms確保し、reload前の残り時間を推測して復元しない。

---

## 40. RandomSource

Penalty chunkでも既存RandomSource契約を維持する。

各die：

```text
OUT-check draw
SAFE only face draw
```

Recoveryによって確定済みchunkのRandomSourceを再消費しない。

---

## 41. Replay

Replayでは以下を維持する。

- Game Mode
- mode-specific configuration
- Dice Mode
- Throw Style
- ROLL limit
- participant identity

変更可能なのはplayer orderのみ。

完走指定のtarget、連続試合のgame countもreadonly。

新しいReplay開始時には以下をresetする。

- cumulative score
- cumulative remaining
- completion count
- Round / Game progress
- Penalty progress

---

New Gameでは現在の以下をSetupへcarryする。

- Game Mode
- mode-specific setting
- Dice Mode

- ROLL limit
- participant information

Setup上で編集可能。

Game progressはcarryしない。

以下はresetする。

- cumulativeScore
- cumulativeRemaining
- totalCompletionCount
- current game number
- Penalty progress

## 44. モード切替

Setup中にGame Modeを変更した場合、非選択モードのauthoritative settingを保持しない。

完走指定を初めて選択：

```text

```

連続試合を初めて選択：

```text

```

隠れた設定を復元しない。

完走指定から離れた後もROLL limitは以前の有限値へ自動復元しない。∞のままとする。

## 49. Mobile Stable Layout

v4でも既存のStable Layout契約を維持する。

対象viewport：

```text
320 × 568
375 × 667
390 × 844
430 × 932
768 × 1024
1280 × 900
```

既存Play / Penalty画面について以下を維持する。

## 50. Stable Layout禁止事項

v4 UI追加のために、既存Play / Penaltyを以下の方法で変更しない。

- element merge
- element reorder
- sticky
- fixed

## 51. Renderer

Normal / Completion Target / SeriesのゲームモードによってRenderer authorityを変更しない。

Rendererは常にalready committed resultを表示するだけ。

Series PenaltyでもRendererへ渡すのは最大10 diceのchunk。

70 dice用Three.js Rendererは作らない。

---

## 52. 2D layout

通常Playでは既存result-card layoutを維持する。

Series Penalty chunkは最大10 diceとし、元Dice Modeとは独立した専用2D layoutを使用する。

```text
10 → 5 + 5
9  → 5 + 4
8  → 5 + 3
7  → 5 + 2
6  → 5 + 1
≤5 → 1 row
```

このSeries Penalty chunk規則を通常Playの5 / 7 / 10 / 14 DICE result layoutへ逆適用しない。

Three.js staging layoutとも分離する。

Series累積Penaltyだからという理由で14～70 dice用result gridを追加しない。

## 53. Ranking separation

Normal / Completion TargetとSeriesではRanking sourceが異なる。

Normal / Completion Target：

```text
current Round player state
```

Series：

```text
cumulativeScore
cumulativeRemainingDice
```

同じ比較functionへ無理に条件分岐を詰め込む必要はない。

実装時には各ranking ruleのauthorityを明確に分離する。

---

## 54. Penalty separation

Normal / Completion Targetはdecisive Roundのremaining diceを使用する。

SeriesはcumulativeRemainingDiceを使用する。

SeriesのPenalty countが10超の場合のみchunk処理を使用する。

通常Penaltyの既存1-roll semanticsを不必要に変更しない。

---

## 55. 完走countの意味

全モードで`totalCompletionCount`はunique completer countではなくcompletion event countとする。

Normalでは既存仕様。

Completion Targetではtarget判定とPenalty multiplierに使用。

SeriesではPenalty multiplierに使用。
