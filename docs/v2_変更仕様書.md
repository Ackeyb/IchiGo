# IchiGo v2 — 変更仕様書

## 1. 文書の目的

本書は、完成済みのIchiGo v1を基準として作成したv2変更設計の履歴である。内容は[docs/SPEC.md](SPEC.md)へ統合済み。実装時の唯一のSource of TruthはSPECであり、本書は第二の正本ではない。

v1で確定済みのゲームルール・ランキング・サドンデス・ペナルティ・OUT・Presentation・Sound・Session Recovery等について、本書に明示された変更点以外は原則として維持する。

文書統合時点の実装はv1（main / 366c732）。以下は設計時の差分記録であり、v2実装済みを意味しない。後続確定事項は末尾に記録する。

---

# 2. v2の主要目的

v2では以下を実施する。

1. 既存UIの細部改善
2. 再戦時のプレイヤー順変更
3. 新しいゲーム開始時の設定引き継ぎ改善
4. Setupでのプレイヤー追加・削除・並び替え改善
5. Dice Modeの導入
6. 固定7ダイス前提のGame Engine一般化
7. 5 / 7 / 10 DICEへの対応
8. 2D / 3Dダイスデザイン改善
9. Session RecoveryのDice Mode対応

---

# 3. Dice Mode

## 3.1 対応モード

v2では以下の3種類を正式対応する。

- 5 DICE
- 7 DICE
- 10 DICE

初回起動時のデフォルトは、

**7 DICE**

とする。

概念上は以下のような型で扱う。

```ts
type DiceMode = 5 | 7 | 10;
```

Dice Modeはゲーム設定の一部として保持する。

---

## 3.2 ゲームルール

Dice Modeによって変更されるのは、ラウンド開始時の初期ダイス数のみとする。

以下の既存ルールは全Dice Mode共通とする。

- 1 = 100点
- 5 = 50点
- 複数の1 / 5はすべて得点
- 得点ダイスは除外
- 得点が存在し、active diceが残っている場合は継続必須
- 次ROLLは手動
- 得点なしでTURN END
- COMPLETE条件
- OUTルール
- Ranking
- Sudden Death判定
- cumulative completion count
- multiplier
- Penaltyルール

Dice Modeごとの独自得点ルールは設けない。

---

# 4. Game Engineの一般化

v1で固定値7を前提としていた箇所を、選択されたDice Modeを基準とする実装へ変更する。

概念上、

```ts
initialDiceCount = diceMode;
```

とする。

以下の不変条件を使用する。

```text
activeDice + strandedDice + removedDice = initialDiceCount
```

固定値7をGame Engineのルール判定に直接使用しない。

---

## 4.1 ラウンド開始

通常ラウンド開始時、

```text
activeDice = initialDiceCount
strandedDice = 0
removedDice = 0
score = 0
completed = false
turnFinished = false
```

を基本状態とする。

---

## 4.2 COMPLETE

COMPLETE条件の意味はv1から変更しない。

```text
remainingDice = activeDice + strandedDice
```

とし、

```text
remainingDice === 0
```

の場合のみCOMPLETEとする。

したがってOUT / stranded diceが存在する場合、そのラウンドではCOMPLETEできない。

Dice Modeによる例外は設けない。

---

# 5. OUT

OUT確率は全Dice Mode共通とする。

- 乱暴：3%
- 普通：1%
- 丁寧：0%

Dice ModeによってOUT確率を変更しない。

OUTは引き続き各active dieへ独立して判定する。

判定順序は、

```text
OUT判定
↓
SAFEの場合のみD6 face決定
```

とする。

OUT dieは、

```ts
status: "out"
value: null
```

を維持する。

ゲームUIでは具体的なOUT確率を表示しない。

---

# 6. Sudden Death

Sudden Death開始時も、現在のゲームで選択されているDice Modeを維持する。

例：

```text
5 DICEゲーム → Sudden Deathも5個
7 DICEゲーム → Sudden Deathも7個
10 DICEゲーム → Sudden Deathも10個
```

Sudden DeathによってDice Modeを7へ戻してはならない。

その他のSudden Deathルールはv1を維持する。

特に、

- original players全員参加
- original order維持
- score reset
- activeDice = initialDiceCount
- strandedDice = 0
- removedDice = 0
- completed = false
- turnFinished = false
- round results reset
- cumulative completion countのみcarry
- unlimited repeat可能

とする。

---

# 7. Penalty

Penaltyのルール自体はv1から変更しない。

Penalty dice countは、

**decisive roundのremainingDice**

とする。

したがって10 DICEでは最大10個のPenalty diceが存在し得る。

Penaltyでは引き続き、

- OUT判定なし
- 1 / 5の特殊得点効果なし
- 一度だけROLL
- 全faceを通常数値として合計
- basePenalty = face sum
- finalPenalty = basePenalty × multiplier

とする。

---

# 8. Dice Result Layout

## 8.1 5 DICE Mode

最大5個。

すべて横1行表示とする。

---

## 8.2 7 DICE Mode

v1のレイアウトを維持する。

最大7個を横1行表示する。

対象モバイル幅を含め、

- wrapなし
- horizontal scrollなし
- clippingなし
- overlapなし

を維持する。

---

## 8.3 10 DICE Mode

10 DICE Modeでは、結果カード領域を**最大5列Grid**として扱う。

表示規則：

```text
10個 → 5 + 5
9個  → 5 + 4
8個  → 5 + 3
7個  → 5 + 2
6個  → 5 + 1
5個  → 5
4個  → 4
3個  → 3
2個  → 2
1個  → 1
```

10 DICE Modeでは、ダイス数が6〜10個の場合に無理に1行へ圧縮しない。

通常ROLLとPenalty ROLLで同じ基本レイアウト規則を使用する。

320 / 375 / 390 / 430pxを含むモバイル幅で、

- horizontal overflowなし
- clippingなし
- overlapなし
- 各faceが判別可能

とする。

---

# 9. Dice Visual Design

## 9.1 1と5

D6のfaceデザインとして、

**1および5の星 / pipを赤色**

とする。

対象：

- 2D dice
- Three.js 3D dice
- 通常ROLL
- Penalty ROLL

Penaltyにおいて1 / 5は特殊効果を持たないが、ダイスデザインそのものは通常ダイスと統一する。

したがって、

```text
赤 = GET
```

という意味にはしない。

あくまで、

```text
face 1 / face 5の視覚デザイン
```

として扱う。

---

# 10. Penalty Result UI

Penalty ROLLでは、

- SAFE
- GET
- OUT

という通常ROLL用status labelを表示しない。

Penalty diceはface valueのみ表示する。

例：

```text
通常ROLL

[ 5 ]
 GET


Penalty ROLL

[ 5 ]
```

Penalty Engineのルールは変更しない。

---

# 11. Penalty Summary UI

Penalty結果の、

- BASE
- MULTIPLIER
- FINAL

を各スクエア内で視覚的に中央配置する。

ラベル・数値ともに中央揃えを基本とする。

数値の桁数が変化しても不自然な左右ズレが発生しないようにする。

Penalty計算ロジックは変更しない。

---

# 12. Turn Action UI

TURN END後に表示される、

- 次へ
- 結果を見る

等の主要Action Buttonが状態によって上下移動しないようにする。

Presentation領域内に安定したAction Slotを確保する。

概念：

```text
Dice Presentation
↓
Result / Message
↓
Action Slot
```

Actionの種類が変わってもAction Slot自体の位置は可能な限り維持する。

固定ページ高さによってcontentをclipする実装は禁止する。

レスポンシブ性を維持する。

---

# 13. 「同じメンバーでもう一度」

v1の即時再戦開始方式を変更する。

Final Resultから、

**「同じメンバーでもう一度」**

を押した場合、再戦準備画面へ移動する。

---

## 13.1 再戦準備画面

再戦準備では前ゲームの、

- Player
- Player names
- Dice Mode
- throwStyle
- Sound setting

を維持する。

Playerの**順番のみ変更可能**とする。

以下は禁止する。

- 名前変更
- Player追加
- Player削除

開始操作によって、選択された新しい順番で次ゲームを開始する。

---

## 13.2 リセット対象

再戦開始時には、

- score
- activeDice
- strandedDice
- removedDice
- completed
- turnFinished
- rank
- round results
- penalty results
- cumulative completion count
- multiplier
- sudden death state

等、ゲーム進行状態を新規ゲーム相当にresetする。

Sound settingは維持する。

---

# 14. 「新しいゲーム」

Final Resultから、

**「新しいゲーム」**

を押した場合、Setup画面へ戻る。

ただしv1と異なり、前ゲームの設定の一部を引き継ぐ。

---

## 14.1 引き継ぐ情報

以下をSetupへ引き継ぐ。

- Player数
- Player names
- Player order
- Dice Mode
- throwStyle
- Sound setting

Setup上でPlayer情報を再編集できる。

---

# 15. Setup Player Management

SetupではPlayerをrow単位で管理する。

**独立したplayerCount設定値を持たず、現在存在するPlayer row数をplayerCountとする。**

これにより、

```text
設定人数 = 4
実Player = 3
```

のような不整合状態を作らない。

---

## 15.1 Player追加

Player追加ボタンを設ける。

最大10人まで追加可能。

追加されたPlayer rowは空欄nameを初期値とする。

---

## 15.2 Player削除

各Player rowに削除操作を設ける。

末尾Playerだけでなく、途中のPlayerも削除可能とする。

例：

```text
田中
佐藤 ← 削除
鈴木
山田
```

削除後：

```text
田中
鈴木
山田
```

残ったPlayerの表示順 / orderを正常化する。

最低Player数は2人とする。

2人の場合、それ以上Playerを削除できない。

---

## 15.3 Player並び替え

SetupではPlayer orderを変更可能とする。

既存の並び替えUIを利用または改善してよい。

追加・削除・並び替え後も内部Player IDと表示orderを混同しない。

Player nameの重複は引き続き許可する。

---

# 16. 「すべて初期状態に戻す」

Setup画面に、

**「すべて初期状態に戻す」**

操作を追加する。

誤操作防止のため、確認Dialogを表示する。

確定後、Setupを初回起動相当へ戻す。

```text
Player数 = 2
Player names = blank
Player order = initial
Dice Mode = 7
throwStyle = normal
```

Sound settingのみ維持する。

Soundはユーザー環境設定として扱い、ゲーム設定の完全初期化には含めない。

---

# 17. Dice Mode Selection UI

Setup画面にDice Mode選択UIを追加する。

選択肢：

```text
5 DICE
7 DICE
10 DICE
```

初回デフォルト：

```text
7 DICE
```

一度選択されたDice Modeは、

- 同じメンバーでもう一度
- 新しいゲーム

では維持する。

「すべて初期状態に戻す」で7 DICEへ戻す。

ゲーム開始後はDice Modeを変更できない。

---

# 18. Throw Style

throwStyleは既存の、

- 乱暴
- 普通
- 丁寧

を維持する。

「同じメンバーでもう一度」では維持する。

「新しいゲーム」でも維持する。

「すべて初期状態に戻す」で、

**普通**

へ戻す。

具体的OUT確率はゲームUIへ表示しない。

---

# 19. Sound

Sound settingはユーザー環境設定として扱う。

以下すべてで維持する。

- 同じメンバーでもう一度
- 新しいゲーム
- すべて初期状態に戻す
- Sudden Death
- reload / Session Recovery

Sound障害がゲーム進行を妨げない既存仕様を維持する。

---

# 20. Session Recovery

Dice Modeをauthoritative game configurationとしてSession Recovery対象に追加する。

reload後も、

- 5 DICE
- 7 DICE
- 10 DICE

の選択状態を正しく復元する。

復元後のGame Engine invariantも、

```text
activeDice + strandedDice + removedDice = initialDiceCount
```

を使用して検証する。

---

## 20.1 Recovery Schema

v2では保存形式変更を伴うため、Session Recovery schema versionを更新する。

推奨：

```text
version 1 → version 2
```

v1形式のRecovery dataをv2が誤ってv2 stateとして復元してはならない。

v1 Recovery dataについては、複雑なmigrationを必須としない。

v2がv1 dataをunsupported versionとして安全に拒否し、新規ゲームへ移行できればよい。

corrupt / unsupported dataを推測修復しない既存方針を維持する。

---

# 21. キャッチコピー

固定の「7」を含む現在のコピーは、Dice Mode導入に伴い変更する。

削除だけではなく、Dice Modeに依存しないコピーへ置き換える。

第一候補：

```text
ONE ROLL AT A TIME
最後のダイスまで。
```

固定ダイス数をコピーへ含めない。

将来的にDice Modeが追加された場合でも変更不要な表現とする。

---

# 22. Responsive Requirements

引き続きsmartphone-firstとする。

最低限以下を対象とする。

- 320px
- 375px
- 390px
- 430px
- 768px
- desktop

以下を禁止する。

- unintended horizontal scroll
- result clipping
- card overlap
- Action Buttonの不自然な移動
- Dialogのviewport外表示

10 DICE Modeを含めて確認する。

---

# 23. Accessibility

既存要件を維持する。

特に、

- touch target
- keyboard operation
- focus management
- Dialog focus restoration
- non-color-only state indication
- reduced motion

を維持する。

1 / 5の赤色化だけをGET判定手段として使用してはならない。

---

# 24. Three.js

Three.js RendererはGame Engineの結果を視覚化するPresentation Adapterであり続ける。

Dice Mode追加後も、

```text
Game Engine
↓
committed DieResult[]
↓
Presentation
↓
Three.js / 2D fallback
```

の責務分離を維持する。

Three.js physics / animationからゲーム結果を決定してはならない。

5 / 7 / 10 diceすべてで、

- cleanup
- timeout
- context loss
- fallback
- resize
- unmount

の既存安全性を維持する。

---

# 25. 2D / 3D Result Consistency

同じcommitted resultに対して、2Dと3Dで異なるface / statusを表示してはならない。

3D failure時も同じ結果を2Dへfallbackする。

fallback時に、

- 再ROLL
- RandomSource再消費
- OUT再判定

を行ってはならない。

---

# 31. 文書統合時の確定事項

- SPEC v2へ統合済み。実装開始前の文書同期のみ。
- 初回Setup、新ゲームSetup、再戦準備、full reset後Setupとその編集・並べ替えdraftを同一タブの復旧対象に含める。最後の正常保存game/draftまで保証する。
- Draft validationとStart validationを分け、空欄・未完成nameだけでdraftをcorrupt扱いしない。
- Game/draft recovery schemaはversion 2。v1ゲームsaveはunsupportedとして拒否可能。Sound形式/versionは独立し、有効な既存設定をgame schema更新だけで破棄しない。
- 再戦準備では順番のみ編集可能。Dice Mode・throwStyleも変更不可。
- コピーは「ONE ROLL AT A TIME」「最後のダイスまで。」を採用。
- 結果カード配置はDice Modeと表示個数から決定し、10 DICE途中の7個と7 DICEの7個を区別する。

詳細・競合時の判断は常に[SPEC](SPEC.md)に従う。
