## 発見事項と修正

1. SPEC §22・§90・§91・§77/29: 完走フラグは確定していたが、累積完走数を加算する実装がなかった。
   `TurnState`へ確定済み累積値を受け渡し、`rollTurn`が完走の確定と同時に一度だけ加算する。
   次のターンには返された値を渡す。Sudden DeathとPenaltyは引き続き加算しない。
2. 通常ROLLの番号は各ターンで1へ戻るため、別ターンの古いROLL／継続要求が番号一致で通った。
   明示的な`turnId`を要求と照合して、乱数生成・状態遷移前に拒否する。
3. Penaltyの要求はプレイヤーIDだけを照合しており、別ゲームの古い要求を区別できなかった。
   明示的な`penaltyId`を要求と照合し、乱数を消費する前に拒否する。
4. `calculatePenalty`は疎配列の欠損要素を検証で飛ばし、1個分の配列から0点を生成できた。
   全要素を走査し、欠損出目も不正として拒否する。通常の乱数生成経路では発生しない入力境界の問題。

上記を5件の回帰テストで先に再現し、修正前の失敗と修正後の成功を確認した。
既存154件の検証内容は維持し、呼び出し引数のみ新しい必須コンテキストへ適合した。

## 横断確認

- 通常ROLL: ダイスごとにOUTを先に判定し、SAFEのみD6を抽選。1/5をすべて得点化・除外。
  完走→activeなし→得点による継続→無得点終了の順序はSPEC §63と一致。
- Invariant: 3種のダイス数の合計は7。残数はactive + strandedの派生値。
  OUTが残る状態から完走は生成されない。通常ROLLの到達状態を列挙して検証。
- Ranking: 完走優先・完走者同率1位・非完走者のscore/remaining比較・1224・同率敗者全員・
  終了者のみの暫定順位は一致。OUT内訳によるタイブレークはない。
- Sudden Death: 全員完走または全員非完走完全同点。全員を元の順番でリセットし、累積値・投げ方を維持。
  ラウンド固有結果は引き継がず、同一ゲーム内の古い開始番号と重複開始を拒否する。
- Penalty: RankingとSudden Deathの既存判定を利用。決着ラウンドの残数を固定し、元の順で個別D6を1回。
  OUT・特殊得点・除外・再ROLLなし。累積値を変更せず、合計×(累積値+1)を確定。
- 2人・10人とも、全員完走のラウンドを2回経て決着し、最終ラウンドの完走を含む倍率で各敗者を処理できる。
- 入力オブジェクトの破壊、通常ROLLとPenaltyのルール混同、React/DOM/Browser API/描画/音の依存は確認されない。
  直接のMath.randomは注入可能な本番用RandomSourceだけに限定されている。
- remainingDice・OUT確率は派生値。Penaltyのダイス数・倍率等は決着時／結果確定時のスナップショット。
  複数の独立した可変Source of Truthとしては扱っていない。

## API利用契約と監査の境界

状態遷移関数は最新状態を受け取り、返された状態を次の要求前に採用する。
`turnId`と`penaltyId`は呼び出し元で再利用せず、要求生成時のIDを保持する。
純粋関数は古い状態そのものの再入力や、初期化関数を再実行して作った別状態を隠れた履歴で検出しない。
低水準の`resolveRoll`や`rollPenaltyDice`を操作受付に直接使わない。
サドンデス開始番号は同一ゲーム内の識別であり、ゲーム切り替え時の要求配送は今後の進行制御で隔離する。

通常ターン・ラウンド・ペナルティのUI進行制御と保存復旧は未実装。
この監査は純粋APIとその接続テストの保証であり、ブラウザー上の操作・復旧の保証ではない。
Phase 1〜4の修正判断に必要な仕様の曖昧さは見つからなかった。
